# Review of the Overnight Autoresearch Run — What Exists Now

This file is a continuation memo, not a judgment of the previous agent.

It reconstructs what the previous run actually accomplished and what remains untested.

---

# 1. Correction to the initial morning read

The first assumption that the overnight run had produced no Git commits was false.

The repository export shows a long AR-001 → AR-017 progression, and the user subsequently confirmed that the run produced **18 commits total**.

Therefore the correct interpretation is:

> the agent performed substantial engineering and experimentation, but the previous program allocated too much of that work to validation/provenance gates and stopped before executing the central RoPE-ND + true self-play + GRPO thesis.

This matters because the next run should reuse the implementation rather than restart.

---

# 2. What AR-001 established

The existing BC path had severe data amplification.

A small load probe selected roughly 2k logical rows but decoded around gigabytes of row-group data and used several GiB of resident memory.

A training smoke was only around 11 rows/s.

This confirmed that the historical BC data path was inefficient.

It was useful evidence at the time.

It is no longer the critical research problem because Stage 4 has already been trained.

---

# 3. What AR-002 / AR-003 established

The previous run implemented a fixed-width packed/mmap representation with exact column parity on bounded probes.

Observed benefits included dramatic reductions in decoded bytes and host RSS.

However complete training wall-clock did not improve monotonically across 1/2/3 epoch tests once one-time ETL and TBPTT/training costs were included.

Conclusion for the continuation:

\[
\boxed{
\text{do not spend the remaining run perfecting historical BC storage}
}
\]

The new self-play loop should use a native rollout buffer rather than reuse Parquet or the packed BC backend by default.

---

# 4. Where the previous program over-constrained progress

AR-004 through AR-007 spent substantial effort on:

- source identity;
- resume contracts;
- exact root gating;
- path variants;
- hardlink/symlink cases;
- packed-loader integration fixtures;
- provenance validation;
- optimizer micro-tests.

This work produced real commits and useful infrastructure.

But State Capsules repeatedly imposed gates equivalent to:

> no self-play / RL run until the packed backend is promotion-grade.

That condition was not required by the actual research thesis.

The new program removes that dependency.

---

# 5. AR-008 was the important transition

AR-008 established a real Stage 4 trajectory collector.

It demonstrated:

- legal autoregressive action sampling;
- behavior log probabilities;
- recurrent memory digests;
- ordered multi-select rows;
- terminal rewards;
- approximately 64 rows/s in the bounded probe.

But it explicitly did **not** execute:

- GRPO;
- long RL;
- true recurrent self-play.

Its mirror mode was `mirror_no_memory`.

That means the opponent's memory was reset rather than evolved as an independent recurrent lane.

---

# 6. AR-009 proved policy mutation works

AR-009 produced an actual PPO-like candidate from current-policy samples.

Important observation:

\[
\theta_{\text{candidate}}
\neq
\theta_{\text{Stage4}}
\]

and the candidate could later be made runnable through the public-agent path.

This proved the basic optimization circuit:

```text
Stage4
→ on-policy samples
→ logprobs
→ gradient update
→ candidate weights
```

works.

That plumbing is reusable for GRPO.

---

# 7. AR-010 through AR-013 made candidates executable

The run then hardened candidate loading and artifact checks.

This was expensive relative to the research objective, but it produced one useful outcome:

> a candidate generated by the RL code can now be loaded by the real agent and evaluated by the real tournament harness.

Do not rebuild this path unless the RoPE-ND architecture requires a serialization update.

The previous run already solved several boring but necessary problems:

- how to retain behavior logprobs;
- how to identify recurrent state inputs/outputs;

The next run can therefore spend a much larger fraction of wall-clock on actual learning experiments.

# 13. What not to inherit from the previous conclusions

Do not inherit the following as current axioms:

> “RoPE-ND remains unjustified.”

It was not tested.

> “PPO exploration should close.”

Only one very narrow family of tiny PPO experiments was tested.

> “Stage 4 is the frozen architecture.”

Stage 4 is the initialization.

> “packed backend must be promotion-grade before RL.”

Fresh self-play can use its own direct buffer.

> “mirror_no_memory is sufficient self-play.”

It is not the requested recurrent self-play.
